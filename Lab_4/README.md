# Lab 4. Авторизація та ролі: «Сервіс ремонту та обслуговування комп'ютерної техніки»

Університетська лабораторна робота: **реалізація авторизації користувачів**
(Passport.js, сесії) та **налаштування захищених точок доступу**
(контролери/дії за ролями) на базі Lab 3.

Ланцюг розробки (кожна лаба — продовження попередньої, оригінальні папки
не змінюються):

- **Lab 1** — реляційна модель даних (15 сутностей, 9 enum, seed, інваріанти І1–І10).
- **Lab 2** — веб-шар: Pug-шаблони, MVC, 13 сторінок.
- **Lab 3** — форми та серверна валідація: CRUD довідників, каталог запчастин.
- **Lab 4** — **авторизація**: 4 ролі (адміністратор, менеджер, майстер,
  відвідувач), вхід/вихід/реєстрація, захист маршрутів, сторінка 403.

## Ролі та матриця дозволів

У моделі вже існували 3 ролі персоналу (`ADMIN`, `MANAGER`, `TECHNICIAN`);
міграцією Lab 4 в enum `Role` додано четверту — **`VISITOR` (відвідувач)**.

Правила захисту (`src/lib/auth.ts` → `requireRole(roles)`):

1. **Не авторизований** на захищеній дії → `302` редірект на
   `/login?next=<повернення>`.
2. **Авторизований без потрібної ролі** → `403` (`views/errors/403.pug`)
   з поясненням, яка роль потрібна.
3. Публічні сторінки перегляду (`/`, `/requests`, `/requests/:id`,
   `/clients`, `/devices`, `/works`, `/parts`) доступні всім, включно з
   гостем без входу.

## Нові сторінки та поведінка

| Маршрут | Опис |
|---|---|
| `GET /login` | форма входу (email + пароль); запит `?next=` — куди повернутись після входу |
| `POST /login` | Passport.js `local` strategy → `bcrypt.compare`; успіх → редірект (або `next`), помилка → 401 + повторна форма з помилкою |
| `GET /logout` | знищення сесії → `/login?loggedout=1` |
| `GET /register` | публічна реєстрація (нові акаунти — роль `VISITOR`) |
| `POST /register` | серверна валідація (Lab 3 паттерн: 400 + `errors[]` + збережені значення); унікальність email; успіх → автовхід → `/` |
| `403` | сторінка «Доступ заборонено» з назвою потрібної ролі |
| `GET /health` | без змін (JSON) |

Кожна мутуюча дія Lab 3 отримала вейдер за матрицею (таблиця вище):
`routes/requests.ts`, `routes/clients.ts`, `routes/devices.ts`,
`routes/works.ts`, `routes/parts.ts`.

## Зміни моделі (міграція)

`prisma/migrations/20261018000000_add_visitor_role/`:

```sql
ALTER TYPE "Role" ADD VALUE 'VISITOR';
```

`prisma/seed.ts`: до акаунтів персоналу додано `visitor@service.ua`
(роль `VISITOR`); залишків від Lab 3 — 60 заявок / 30 клієнтів / 45 пристроїв.

## Сесії

- `express-session`, секрет — `SESSION_SECRET` (`.env.example`), cookie
  `httpOnly` + `sameSite=lax`, `maxAge` 8 годин, `saveUninitialized: false`.
- У сесії зберігається **лише id користувача** (serializeUser/deserializeUser);
  роль читається з БД на кожному запиті — зміна ролі діє негайно.

## One-click launch (Windows)

Подвійний клік **`start.bat`** — перевіряє Docker, збирає образ, піднімає
PostgreSQL 18 + додаток, застосовує міграції (включно з новою Lab 4),
насичує демо-даними, запускає сервер → **http://localhost:3000**.

Зупинити все — **`stop.bat`** (скинути дані: `docker compose down -v`).

## Тест-план (ручна/автоматична перевірка)

1. `GET /` як гість — 200, у шапці посилання «Вхід».
2. `POST /login` з помилковим паролем — 401, банер «Невірний email або пароль».
3. Вхід `visitor@service.ua` / `secret` — 200, шапка: «Відвідувач Сервісу [Відвідувач]».
4. Як відвідувач: `GET /clients/new` → **403** (потрібні «Менеджер, Адміністратор»).
5. Вхід `tech1@service.ua`:
   - `GET /requests/new` → **403** (створення заявок — менеджер+);
   - на картці заявки форми робіт/запчастин/діагностики — доступні, `POST` працює;
   - `GET /clients/new` → **403**.
6. Вхід `manager@service.ua`:
   - `GET /clients/new`, `/devices/new`, `/works/new`, `/parts/new`, `/requests/new` → **200**, `POST` працює;
   - на картці заявки — форма оцінки/рахунку/оплат/гарантії.
7. Вхід `admin@service.ua` — доступ до всього, включно з видаленням.
8. `GET /logout` → на `/login` з банером «Ви вийшли з системи».
9. `POST /register` (новий email + пароль ≥8) — акаунт створюється, авто-логін,
   роль «Відвідувач»; повторний реєстр на той самий email — 400 «Email уже
   використовується».
10. Гість натискає «Новий клієнт» (URL `/clients/new`) → редірект на
    `/login?next=%2Fclients%2Fnew`; після входу повернення на цю сторінку.
