# AGENTS.md — правила роботи з репозиторієм

Репозиторій університетських лабораторних робіт (курс «Вебтехнології»,
студент Багрій-Белз Андрій, гр. КН-2327Б). Кожен `Lab_N/` — самодостатній
проєкт: власний код, Docker, документи, звіт.

## Жорсткі правила (не порушувати)
1. **Без HTML5 `required`** у формах — валідація серверна (400 + збереження
   введених даних + банер помилок), патерн ЛР-3.
2. **Звіти правдиві:** скріншоти звіту `Lab_N/report/` — тільки з реального
   запущеного билду **цього** лаба (не сусіда).
3. **Комунікація з користувачем — українською**; коміт-повідомлення — UA.
4. **Верифікація обов'язкова** після змін: `npx tsc --noEmit` (чисто) →
   docker build+start → `scripts/lab{N}-smoke.ps1` (усі PASS).
5. Кожна поведінкова зміна — новий запис у `Lab_N/docs/DECISIONS.md`
   (нумерація D… продовжується окремо в кожному лабі).

## Docker (важливо)
- Контейнери/БД/порти **спільні між лабами** (`lab1_service_db`,
  `lab2_service_app`, 3000/5433) — **одночасно працює лише один лаб**.
- Перемикання лаб: `docker compose down` у старому (a не `stop` — інакше
  conflict по ім'ях контейнерів), потім `docker compose up -d --build` у новому.
- `SESSION_SECRET` обов'язковий (fail-fast у `src/lib/auth.ts`): значення в
  `docker-compose.yml` та `.env.example` кожного лаба (`labN-local-dev-secret`),
  в локальному gitignored `.env` теж.
- Вивід `git push`/`docker` у stderr → PowerShell дає NativeCommandError і
  exit 1 навіть при успіху; орієнтуватися на текст (`x..y main -> main`),
  а не на код виходу.

## Демо-дані (лаби 4–6)
`admin@ / manager@ / tech1@ / tech2@ / visitor@service.ua`, пароль `secret`.
Картинка прав: відвідувач — read-only, майстер — статус/роботи/діагностика,
менеджер — довідники+фінанси, адмін — все (+`/users` у 5–6, `+ /api` у 6).

## Звіти (report-maker)
- Джеріло: `Lab_N/report/report_maker_input_labN.json` →
  `generate_report.py <json> --out Lab_N/report --format both`;
  PDF перекласти в `report/.rendered_pdf/`.
- Перевірка docx — напряму (`zipfile`: текст `document.xml` + md5
  `word/media/` зі скріншотами), рендер сторінок може бути застарілим.
- Фрагменти коду в JSON звіту мають узгоджуватися з актуальним джерелом
  перед перегенерацією.

## Код
- Лаби спільнокореневі: спільні файли часто **ідентичні** (`requests.ts`
  у 4/5/6). Перед правками перевірити `git diff "HEAD:Lab_a/f" "HEAD:Lab_b/f"`;
  якщо оригінали однакові — портувати одне виправлення скрізь.
- HTTP-статус помилок — **до** `render`/`redirect` (Express фіксує статус
  при перших байтах).
- Автор записів — виконавець (`req.user.id`), ніколи «перший ADMIN із БД».
- `today()` — функція за моментом запиту, не модульна константа.
- `@unique`-конфлікти (P2002) → 400 «Конфлікт даних», не 500.
- Складні заміни в pug/ts через edit-інструмент: один діапазон = одна
  операція на виклик; після мультиоп-виклику перечитати ділянку.
