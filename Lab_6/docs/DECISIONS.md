## Lab 6 — RESTful API (2026-10-18)

| # | Рішення | Обрано | Обґрунтування |

| D53 | API як шар над web-контролерами, а не окрема логіка | Мутації `/api` викликають ті samі web-контролери (Lab 3–5) через `runWeb` (захоплення `redirect/status/render` у JSON-статуси): `302` → 200/201 + dofetch сутності; `400 render` → `400 {"error","errors"}`; 404 — `404 {"error":"Not found"}`. Читання — окремими JSON-хендлерами (`api/lists.ts`) з пагінацією | Дві реалізації однієї валідації = розбіжності та подвійне тестування; виклик web-контролерів гарантує: однакова валідація (опис 5–500, номер R-YYYY-NNNN, I4, WARRANTY_CLAIM, суми, залишок оплати, статусна машина) для Web і REST. Альтернативи (окремий service-шар — рефакторинг 15 контролерів; повне дублювання — ~1000 рядків) відхилено як зайвий обсяг/риск |
| D54 | Аутентифікація та коди помилок | Та сама сесія Passport (Lab 4) для Web і API; вейдер `apiAuth(roles)`: без сесії → `401 {"error":"Authentication required"}`, не та роль → `403 {"error":"Forbidden","requiredRoles":[…]}`; коди Prisma мапяться на JSON: P2002/P2003 → 400, P2025 → 404, інше → 500 `{"error":"Internal server error"}` (router-level error-handler, HTML-обробник не торкається `/api`) | REST-семантика: 401 (неавторизований) і 403 (немає прав) — різні коди; в Web це редірект/403-сторінка. JSON-обробник помилок всередині routera — ізоляція від глобального HTML-500 без змін до app.ts |
| D55 | Формат відповіді та семантика методів | Списки: `{data, page, pageSize, total, totalPages}` + `?page&pageSize&q` (pageSize ≤ 100); картки/сущності: `{data}`; створення — 201, оновлення — 200, видалення — 204; помилки — `{"error", "errors"?}`. Методи: `POST` — колекції, `PUT /:id` — заміна, `DELETE /:id`; додано RESTful-аліаси DELETE (web-маршрути збережені без змін). `GET /api/users` — ADMIN (email — персональні дані) | Стандартна REST-конвенція, передбачувана для клієнта; 204 для DELETE (без тіла) — RFC 9110. Web-маршрути (`/clients`, `/users`) лишилися як є — Web-клієнт (Pug) не чіпався, а API додався паралельно |
| D56 | Обсяг API | 36 точок: повний CRUD 5 довідників + заявки (створення/редагування/видалення/статус) + 8 секцій картки заявки (роботи, запчастини, діагностика, оцінка/approve/reject, рахунок, оплати, гарантія, коментарі, вкладення) + користувачі — усі 15 таблиць моделі крізь REST | ТЗ: «доступ до даних системи та управління ними відповідно до індивідуального завдання» — покриває всю модель; матриця ролей 1:1 з Web (D46) — одне джерело правди для обох інтерфейсів |
